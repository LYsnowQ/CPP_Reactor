# 0003 — `/sql` 仅作为演示端点保留

- 状态：accepted（部分实施：默认关闭 + 只读护栏）
- 日期：2026-11-06
- 相关：[HTTP-API.md §4/§6](../architecture/HTTP-API.md)、[BACKLOG B-01/B-02](../plan/BACKLOG.md)

## 背景

`/query` 与 `/sql` 通过 URL 参数执行任意 SQL，用于验证“HTTP → 异步执行 → 跨线程回写”链路。
它没有鉴权、没有语句白名单，配置里的 `readOnly` 也未被执行。同时，静态文件服务会把
`config/SQLConfig.json` 作为普通文件返回。

这带来一个必须显式回答的问题：是补齐安全能力，还是明确它只是演示？

## 决策

**保留端点，但把它定义为“仅本机/隔离网络的演示能力”**：

1. 在 README、HTTP-API 文档中显著标注安全边界；
2. 不把“无鉴权”视为 bug 立即删除，因为它是 SQL 异步链路唯一的端到端入口；
3. 任何公网/多人部署前必须先完成 B-01（拒绝写语句 / 配置移出静态根 / 增加关闭开关）；
4. 不在文档中声称 `readOnly` 生效。

## 理由

- 项目定位是学习，不是产品；删除端点会让 SQL 链路无法演示；
- 立即实现鉴权/白名单会把范围扩大到 Web 安全，偏离 Reactor 主线；
- 但“沉默的危险”不可接受，因此用文档 + backlog 明确边界。

## 后果

正面：

- 保留完整可运行的 SQL 演示链路；
- 风险被显式记录，读者不会误以为它可上线。

负面：

- 仍是已知安全缺陷；任何误部署都可能执行任意 SQL；
- 文档需要持续维护这条警告，避免被后续改动淡化。

## 替代方案

| 方案 | 放弃原因 |
|------|---------|
| 删除 `/sql` | 失去异步 SQL 的唯一演示入口 |
| 仅允许 `SELECT` | 仍需词法判断，易被绕过；且完整实现超出当前范围 |
| 改为 `POST` + 令牌 | 改变演示方式，且令牌管理引入新配置面 |

## 重新评估条件

- 准备把服务放到任何共享网络；
- 需要演示写操作或事务；
- 决定把项目升级为“可部署 demo”而不是纯学习项目。

## 实施更新（2026-11-06，issue #1）

- `/query`、`/sql` 改为**默认不注册**，需追加 `--enable-sql`；
- `readOnly: true` 时启用 HTTP 层启发式护栏：仅允许单条
  `SELECT` / `SHOW` / `DESCRIBE` / `EXPLAIN`，写语句返回 403；
- `readOnly: false` 显式允许任意 SQL，启动日志给出警告；
- 仍未解决：无鉴权、静态根可下载配置（B-02）、数据库失败挂起（B-03）。
  因此“不要暴露到公网”的结论不变。
