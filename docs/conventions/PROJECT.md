# PROJECT.md — 项目定位与完成定义

## 1. 定位

CPPReactor 是一个**个人学习型 C++20 网络服务器**，目标是把以下主题各走通一遍，并留下可复查的
代码、测试与文字记录：

- Reactor 多线程模型与 epoll / poll / select 三种事件分发后端；
- HTTP/1.1 增量解析、Keep-Alive、连接生命周期与回收；
- 静态文件服务与路径安全；
- MySQL 异步查询（线程本地连接、跨线程回调）；
- 可观测性（指标采集与窗口日志）；
- 构建、容器化、压测与工程文档。

它不是产品，也不以“能上线”为目标。

## 2. 明确的非目标

| 非目标 | 原因 |
|--------|------|
| TLS / HTTP/2 / WebSocket | 超出学习范围，引入依赖会盖过 Reactor 主线 |
| 生产级鉴权、限流、审计 | 由“学习项目”定位决定；`/sql` 仅作演示 |
| 多数据库 / 连接池产品化 | 当前只验证 MySQL 单连接模式 |
| Windows 原生支持 | 代码直接使用 epoll 与 POSIX API |
| 多人协作流程（stage 预发布、审批人） | 单人维护，规范按此裁剪 |

## 3. 授权与安全边界

1. 仓库是公开学习项目，**任何提交都会进入公开历史**，不得提交真实数据库密码、令牌、内网地址。
2. `config/SQLConfig.json` 只保留空凭据模板；本机真实配置不得提交。
3. `/sql` 与 `/query` 会执行请求中的任意 SQL，默认只应监听本机或隔离网络。
4. 未经所有者明确同意，不得：
   - 推送 tag 或创建 GitHub Release；
   - 在远端创建/关闭 issue；
   - 改写已发布的历史提交或已打 tag 的提交；
   - 删除 `third_party/` 中的二进制依赖（会破坏 clone 后直接编译）。

## 4. “完成”的定义

一个改动只有同时满足以下条件才算完成：

- [ ] 代码可编译：`make clean && make -j"$(nproc)"` 零错误、零警告；
- [ ] 测试通过：冒烟 + HTTP 边界用例；涉及 SQL 时说明数据库验证范围；
- [ ] 文档同步：受影响的 README / architecture / config / API 文档已更新；
- [ ] 记录同步：`CHANGELOG.md` 的 `[Unreleased]` 已补条目；
- [ ] 没有新增绝对路径、真实凭据、生成的产物；
- [ ] 提交信息符合 [GIT-WORKFLOW.md](./GIT-WORKFLOW.md)，一次提交只做一件事。

> 只改文档的提交不需要跑压测，但仍需通过 `python3 scripts/check_docs.py` 与（若可用）
> 一次完整编译，避免“文档改完才发现代码路径写错”。

## 5. 质量优先级

1. **正确性与资源安全**（生命周期、并发、越界、路径穿越）；
2. **可验证性**（测试、可复现命令、明确的验证边界）；
3. **可读性与文档一致性**；
4. 性能。性能结论必须带环境与复现命令，不能用单次数字下结论。
