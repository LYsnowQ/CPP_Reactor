## 背景

[规范化审计](../reviews/2026-11-06-NORMALIZATION-AUDIT.md) 确认了 4 个 p0/p1 问题：

1. `/sql` 执行任意 SQL，`readOnly` 未生效；
2. 静态根可下载 `config/SQLConfig.json`；
3. 数据库不可达时 `/sql` 永久挂起；
4. `SQLConfig` 多数字段未生效、启动校验未接线。

## 逐项交付

### #1 默认关闭 SQL + 只读护栏（`429dcaf`）

- 新增 `--enable-sql`；未开启时不注册 `/query`、`/sql`，也不读取 SQL 配置；
- `readOnly: true` 时启用 `isReadOnlyStatement()`：仅允许单条
  `SELECT` / `SHOW` / `DESCRIBE` / `DESC` / `EXPLAIN`；
- 写语句、多语句、注释前缀一律 403；`readOnly: false` 显式允许任意 SQL 并告警；
- 新增 `tests/test_sql_security.sh`，HTTP 用例增加到 5 条。

### #2 静态敏感路径拒绝（`305dea2`）

- `StaticFileHandler` 按根目录相对路径拒绝第一段 `config`、任意段以 `.` 开头的路径（403）；
- 目录索引同步隐藏这些条目；
- 新增 4 条 HTTP 用例；413 用例在 `BrokenPipe` 时保留已读响应。

### #3 异步失败回写（`3fefb06`）

- `SqlHandler` 在 job 内捕获 `std::exception` 与未知异常，经 `EventLoop::post()` 回写 500；
- `SqlExecutor::submit()` 返回 false 时同步回 503；
- 连续 3 次“数据库不可达”用例，确认不挂起、工作线程不卡死。

### #4 配置接线与清理（`221df66`）

- 启动改用 `loadSqlConfigFromFileOrThrow()`，`--enable-sql` 时执行 `validate()`；
- `pingBeforeUse` / `maxConnLifetimeMs` / `maxConnIdleMs` 接入 `ThreadLocalConnOptions`；
- 移除从未生效的 `driver`、`connMode`、`reconnect*`、`initSqls`、`slowQueryMs`、
  `enableSqlLog`，同步 `config/SQLConfig.json` 与 `docker-entrypoint.sh`；
- 新增“空配置启动失败”用例。

### 额外修复：Makefile 头文件依赖

修改 `SqlConfig.hpp` 后做增量构建，出现新旧对象 ABI 混用导致启动即段错误。
`Makefile` 增加 `-MMD -MP` 并 `-include` 依赖文件，避免再次链接旧对象。
这是本次修复过程中实际踩到的问题，记录在 #4 的提交里。
